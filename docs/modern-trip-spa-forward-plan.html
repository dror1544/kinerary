Decisions from organizer review

Routing

Current routing is acceptable for now

Keep the four-tab mobile structure, but interview on design issues per part. Desktop/tablet can become richer without changing the core mobile route model.

Bot name

Display only, settings later

The bot name comes from the trip-creation interview. Modern should display that name and open Telegram. Organizer bot-setting improvements require Hermes agent updates and are future scope.

Classic fallback

Fallback is required, but currently suspect

Organizer plan editing may stay Classic-only during member stabilization, but the Modern-to-Classic switch must be fixed before Classic can carry that responsibility.

Moments

Make memory capture more active

Moments should become the home for photos and memory capture, but not as a blank writing box. It should suggest memories from photos, ratings, group chat signals, and the active trip day.

Immediate build order

1

Review and stabilize structure/design

Interview on Today, Journey, Moments, More, desktop/tablet routes, and mobile behavior. Fix the Classic switch before relying on Classic fallback.

2

Bookings/tickets/maps first

Bookings center, confirmation/ticket upload, wallet files, Google Maps/Waze, and contextual attraction enrichment.

3

Organizer plan editing

Rebuild plan edit/diff/revision UX after the member route structure is stable. Until then, keep Classic as the editor fallback.

4

Budget, readiness, rating, photos

Then rebuild Budget, tasks/packing, attraction rating, and photo-led Moments. Trivia, richer gamification, and less-used Classic features can follow later.

Design interview prompts for the next pass

  • Today: should the top of the screen feel more like a countdown/story card, an operations dashboard, or a playful “what now?” assistant?
  • Journey: should phases feel like destinations, chapters, hotels, transport legs, or a mix depending on trip structure?
  • Bookings/tickets: should members usually access them from the day card, a dedicated Bookings screen, or both?
  • Moments: during the active trip, what should the app ask people to do: rate a place, react to photos, answer a tiny prompt, upload one photo, or all of these depending on the day?
  • More: which Classic fallback links should stay visible to members, and which should be organizer-only?

Acceptance gate

Modern can become selectable for production trips only when every Classic workflow either has Modern parity or a consciously accepted Classic fallback. Modern should become the default only after one real test trip validates mobile, RTL/LTR, offline read behavior, operational links, privacy, and organizer rollback.
