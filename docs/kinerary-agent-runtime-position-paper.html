1. חזון המוצר — נקודת המוצא

Kinerary אינו workflow automation לטיולים ואינו chatbot לתיירות. הוא Companion מתמשך: חבר לטיול שמכיר את האנשים, מבין את הקבוצה, חי את הטיול, לומד מהחוויות ומעצים אותן לאורך זמן.

האתר וה־AI הם שני surfaces של אותה intelligence. לפני הטיול Kinerary לומד ומכין; בזמן הטיול הוא מבין “מה קורה עכשיו”, מכוון, מזהיר, מציע, מתאים את התוכנית ומשתתף בחוויה בלי להשתלט עליה; לאחר הטיול הוא משמר זיכרונות ולמידה שמעשירים את הטיול הבא.

BEFORE TRIP          PREPARATION             LIVE TRIP              AFTER TRIP          NEXT TRIP
    |                     |                      |                       |                   |
 learn people  --->  build shared context ---> observe + assist ---> learn experience ---> know them better
    |                     |                      |                       |                   |
 preferences          constraints            location / energy      memories             better defaults
 relationships        bookings               live changes           learned prefs        better suggestions
 expectations         itinerary              proactive help         shared history       stronger relationship

ה־moat המצטבר הוא לא prompt ולא harness. הוא ההיכרות המתמשכת עם המטיילים והקבוצה, ההיסטוריה המשותפת, והיכולת לתרגם אותה להחלטות רלוונטיות בזמן אמת.

2. מה אסור להפסיד בדרך

Relationship

רציפות בין טיולים

המערכת צריכה לדעת לא רק “מהו הטיול”, אלא “איך האנשים האלה אוהבים לטייל”.

Social

הבנת הקבוצה

העדפות אישיות, העדפות משותפות, התנגשויות, קצב, ילדים/מבוגרים ודינמיקה קבוצתית.

Live

מודעות למצב הנוכחי

זמן, מיקום, מזג אוויר, עייפות, מה כבר קרה, anchors קרובים ושינויים חיים.

Learning

Experience feedback loop

לא רק מה אמרו שאוהבים — גם מה בחרו, דחו, האריכו, צילמו וביקשו שוב.

Proactive

יוזמה מדודה

לדעת מתי להציע “צאו עכשיו” או “יש חלופה טובה יותר”, וגם מתי לא להפריע.

Trust

פרטיות והקשר

להשתמש במידע רגיש כדי לעזור בלי לחשוף אותו לאנשים הלא נכונים.

3. התאמה למסמכי הפרויקט ול־PRים

מסמכי FamilyTrip מגדירים את הסוכן כ־contextual family-trip companion, לא concierge גנרי: הוא אמור להכיר itinerary, participants, preferences, reservations, current location והקשר שיחת הקבוצה, ולדבר כמו אדם שכבר נמצא בתוך הטיול. המסמכים גם קובעים שההפרדה בין family group לבין organizer-private context היא גבול מוצרי ואבטחתי.

Evidenceמשמעות
FamilyTrip handoff: companion חם בקבוצה, operator/planner בפרטי.Persona, privacy ו־capabilities תלויי context; לא memory אחד גלובלי.
Planning rules: current time/location, hard anchors, human buffers, active plan, live corrections.ה־companion צריך Situation Model חי, לא רק conversation history.
PR של Sprint 5 חשף session/context leakage, tool fallback ו־chat identity ambiguity.זיכרון וזהות אינם יכולים להישאר סמנטיקה פנימית של harness.
Interviewer lifecycle design נע לכיוון ephemeral execution + deterministic orchestration.LangGraph מתאים ל־workflow lifecycle, אך אינו תחליף ל־longitudinal companion.
Modern trip SPA מתקדם כ־product surface עצמאי.האתר יכול להפוך ל־living surface של אותה intelligence, לא רק תצוגת itinerary.

5. Context & Memory Fabric — הנכס המרכזי

אין לאחסן “memory” כערימה אחת של embeddings או transcript. סוגי ידע שונים דורשים authority, retention, confidence ו־visibility שונים.

Canonical factsתאריך לידה/גיל רלוונטי, מגבלת ניידות מאושרת, dietary restrictionמפורש; שינוי מבוקר
Explicit preferences“אנחנו אוהבים בקרים רגועים”גבוהה; נשמרת בין טיולים לפי scope
Learned preferencesנראה שהקבוצה מעדיפה שווקים על מוזיאוניםconfidence + evidence + decay/revalidation

7. התפקיד הנכון של Hermes, LangGraph ו־Pi

טכנולוגיההתפקיד המתאיםלא להפוך אותה ל־
Hermesalways-on conversational agent runtime, channels, tools, existing companion execution.source of truth לזיכרון, membership או trip authority.
LangGraphdurable multi-step workflows, interviewer, approvals, pause/resume, recovery, long-running actions.ה־relationship model או כל שיחת companion.
Pilightweight replaceable agent loop/runtime כאשר נדרשת שליטה ופשטות.סיבה לבנות מחדש persistence/orchestration שכבר קיימים.

אין צורך לבחור מנצח יחיד. אותו מוצר יכול להשתמש ב־Hermes ל־companion chat, ב־LangGraph ל־booking/onboarding workflow וב־Pi לניסויים או workloads קלים — כל עוד כולם צורכים אותו Context/Memory/Capability contract.

8. Model Gateway — OpenAI, Anthropic, OpenRouter

בחירת מודל צריכה להיות לפי capability של משימה, לא לפי harness. מודל ללא native tool calling עדיין יכול לשמש extraction, summarization, classification, preference inference או structured decision; node deterministic מבצע את הפעולה.

task
 |
 +-- needs tools? ------------> tool-capable model
 +-- structured extraction? --> structured-output model
 +-- deep judge/reasoning? ---> strong reasoning model
 +-- cheap summarization? ----> low-cost model
 +-- conversation? -----------> tone/latency optimized model

Fallback חייב להיות capability-aware ו־fail-closed: אין downgrade שקט ממודל tool-capable למודל שאינו מסוגל לבצע את החוזה.

9. האתר החי כחלק מה־Companion

האתר אינו static itinerary שה־AI יכול לערוך. הוא living trip surface שמציג את אותו state וה־intelligence שה־companion משתמש בהם.
                          Kinerary Intelligence
                                  |
              +-------------------+-------------------+
              |                   |                   |
              v                   v                   v
             Chat              Living Site        Notifications
        ask / discuss       now / today / next     proactive nudges
        private/group       live plan changes      material changes
        shared moments      bookings / photos      reminders
                            recommendations         experience prompts

ה־site יכול בעתיד להציג “עכשיו”, “הבא”, שינויים מהתוכנית המקורית, המלצות מותאמות, זיכרונות ותמונות, ולתת ל־companion feedback signals — תוך שמירה על מקור אמת משותף.

10. הערך למוצר, לארכיטקטורה וליציבות

Product moat

היכרות מצטברת עם אנשים וקבוצות משתפרת מטיול לטיול ואינה תלויה בספק AI.

Better live experience

המלצות נובעות מהמצב האמיתי ומהאנשים הספציפיים, לא מרשימות תיירות גנריות.

Trust

private/shared/inferred scopes מאפשרים personalization בלי disclosure לא רצוי.

Runtime portability

Hermes Cloud, self-hosted Hermes, Pi או LangGraph deployment הם החלטות תפעוליות.

Resilience

agent crash אינו מוחק relationship memory או business state.

Cost control

model routing לפי node/capability מאפשר להשתמש במודל חזק רק במקום שמוסיף ערך.

11. משמעות ה־refactoring

השלב הראשון אינו Hermes → LangGraph. הוא extraction של נכסי המוצר מה־harness.

             EXTRACT FROM HARNESS
                    |
      +-------------+-------------+
      |             |             |
   identity       memory       capabilities
      |             |             |
      +-------------+-------------+
                    |
             OWNED BY KINERARY
                    |
         +----------+----------+
         |          |          |
       Hermes    LangGraph     Pi

מומלץ להגדיר ארבעה contracts:

Contractאחריות
AgentContextuser/trip/channel/role/capabilities; נוצר ומאומת בשרת.
MemoryContextfacts, preferences, learned evidence, group context, visibility, freshness.
CapabilityContextאילו reads/writes/tools מותרים באותו execution.
ExecutionContextexecution/thread identity, lifecycle, tracing, resume/cancel/idempotency.

מעליהם ניתן להגדיר AgentRuntime כ־adapter. המטרה בשלב הראשון: zero product behavior change.

12. מתי נכון לבצע

לא לבצע rewrite בזמן שה־onboarding E2E עדיין מתייצב. צריך baseline עובד כדי לדעת אם migration שיפר או שבר.

כן לבצע עכשיו את ה־seams: כאשר מוסיפים קוד חדש, לא להוסיף עוד Hermes-specific identity/memory semantics. לקבע execution identity, capability boundary ו־memory ownership לפני שהם מתפזרים.

LangGraph pilot: אחרי ש־Sprint 5 contracts יציבים ונעשה live-run נוסף, ובמקביל יש contract אמין מ־confirmed intake ל־provisioning job. אין צורך לחכות למעבר k3s.

13. סיכונים

סיכוןMitigation
הפיכת המוצר ל־workflow engineCompanion intelligence ו־memory הם שכבה נפרדת; graph רק במקום שבו lifecycle מצדיק אותו.
Memory fragmentationKinerary-owned schema/API; harness memory אינו canonical.
False learningevidence + confidence + provenance + decay + user correction; לא להסיק preference קבוע מאירוע יחיד.
Privacy leakagememory scopes ו־policy-aware retrieval; private fact יכול להשפיע בלי להיחשף.
Context overload / costretrieve only relevant memory; summaries; freshness; avoid dumping history into every prompt.
Duplicate side effectsidempotent mutation APIs ו־operation keys.
Framework lock-indomain state ו־memory contracts אינם LangGraph/Hermes objects.
Proactive annoyancerelevance threshold, quiet hours/context, rate limits, explicit preference for intervention level.
Capability fallbackmodel selection fail-closed; never silently route tool task to incapable model.

14. Roadmap מדורג

PHASE 0 — NOW
ייצוב onboarding. לסיים/לאמת את Sprint 5 וה־live findings. לשמור baseline עובד.
PHASE 1
Companion Contracts. AgentContext, MemoryContext, CapabilityContext, ExecutionContext. Hermes נשאר runtime יחיד; zero behavior change.
PHASE 2
Memory ownership. להגדיר canonical/explicit/learned/experience/situation memory, scopes, provenance ו־retrieval API. להתחיל רק במה שה־MVP באמת צורך.
PHASE 3
Capability Gateway. trip-scoped reads/writes, documents, active plan, audit ו־idempotency מחוץ ל־harness.
PHASE 4 — PILOT
LangGraph interviewer. deterministic lifecycle + conversational nodes + interrupt/resume + abandonment/judge. test/shadow לפני cutover.
PHASE 5
Companion learning loop. להתחיל signals מפורשים ופשוטים: likes/dislikes, skipped item reason, organizer correction, repeated preference. לא לבנות “AI psychology engine”.
PHASE 6
Proactive intelligence. situation model + relevance policy + bounded notifications. למדוד usefulness מול annoyance.
PHASE 7
Runtime/model choice by workload. Hermes/Pi/LangGraph ו־OpenAI/Anthropic/OpenRouter לפי reliability, capability, latency ועלות.
PHASE 8 — FUTURE
Cross-trip relationship. traveler/group memory שממשיך לטיול הבא תחת consent ו־privacy controls. זהו ה־moat ארוך הטווח, לא prerequisite ל־onboarding MVP.

15. המלצה סופית

להמשיך את ה־MVP בלי migration disruptive, אבל לשנות כבר עכשיו את כיוון הגבולות: Kinerary צריך להיות הבעלים של relationship, context, memory, trust ו־capabilities. Hermes/LangGraph/Pi מבצעים עבודה עבור ה־Companion — הם אינם ה־Companion.

כך לא מאבדים את החזון בדרך ליציבות. להפך: ההפרדה הופכת את חזון “החבר לטיול” לנכס מוצרי מפורש ועמיד. ככל שה־runtime והמודלים יתחלפו, Kinerary ימשיך להכיר את האנשים, להבין את הטיול וללמוד מהחוויות שלהם.
