## What every scenario verified

1. Preflight: API ready (51 migrations), deployed code carries document reading,
   confirm-starts-build and planned-places; the interview is agentless and both
   runners are configured.
2. The relay is pointed at a local Telegram stand-in and an automated organizer
   signs up (auto-approved), takes the interview and confirms.
3. Confirm writes an immutable intake version and starts the build by itself;
   the provisioning job succeeds and the slug is promoted.
4. Site: topology written, container on the LAN, HTTP 200, a `trip.config.json`
   with this trip's title.
5. Content: every expected stop is present; places named in the documents
   survive as venues with `https` Google Maps and Waze links.
6. As a traveller: logged out, trip data is refused; the trip password logs in;
   every stop and every named place is served; the living itinerary answers.
7. Companion: profile rendered (SOUL, config, profile), SOUL is this trip's,
   gateway running, enrolled with the relay under exact routing, chat bound.
8. MCP: trip-mcp registered, enabled, answering with the trip tools.
9. Teardown: profile backup, gateway uninstalled, bridge stopped, Cloudflare,
   NPM and LXC removed, bindings closed and slug retired, deploy dir moved to
   `retired-trips/`, profile deleted and stayed gone, no s6 supervisor left.

After the last scenario the relay was restarted against `api.telegram.org`.

## The run before it

at the content stage: five stops reached the site and *"'Tokyo Skytree' was in
the document and is on no phase — neither a venue nor a day item"*. multi and
manual were green; exit 1. `39ba81e` rewrote the document-extraction prompt so
its examples and rules match what the code accepts. On the live extraction
evaluation (`control-plane/api/tools/extract-intake-eval.mjs`, same model,
16 scenarios × 2 runs, some built on private documents kept out of the repo),
facts lost went from 18 to 5, unsupported answers from 2 to 0 and wrong
dates or times from 6 to 2. The commit message quotes 2 lost facts; the final
count is 5.

One passing run per scenario is evidence, not a guarantee: extraction output
varies from run to run.
