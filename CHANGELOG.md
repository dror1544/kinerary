# Changelog

## How this file works

- Newest sprint on top. Inside a sprint, newest entry first (by merge date; ties by PR number, highest first). There are no version tags: the sprint is the version unit.
- Every entry says what changed and for whom, and why it matters. New features lead with the value; fixes lead with the problem. References follow on one line: issue (`#n`), PR (`PR #n`), or a short commit hash only when neither exists.
- Each sprint is an H2 with a bold status line. A closed sprint gets a CLOSED status line (date and merge commit) and a boundary marker at the bottom of its section, so an entry from a different sprint is visibly across a line.
- To open the next sprint: add a new `## Sprint N` section ABOVE the previous one, separated by `---`, and change the previous sprint's status line to CLOSED.

## Sprint 6 — Verification, explicit activation, dashboard, and demo rehearsal (2026-09-20 → open)

**OPEN — unreleased. On integration/sprint-6; not yet on main, not deployed.**
Baseline: `97582b6`. Release: none yet. Scope and track breakdown: `docs/sprint6-tracks.md`.

### New

- **The team can now see how the assistant is being used in a trip's chats without reading a single message.** A new event record notes, for each trip, that a group message was or was not addressed to the assistant, that a request was handed to it, that a reply went out and whether Telegram accepted it, that a turn was lost because nothing could take it, and how the assistant's document reading ended. It holds no message text, no names, no chat or user identifiers and no file names, and the database refuses anything else. It never records a turn as "answered", because it sees delivery, not what the assistant did. Benefits the team, and later the organizer report. **Ships off and is not switched on anywhere**: it records nothing until an operator turns it on. Not built yet: the assistant-side collector, the intake route, the rates, the daily report, the dashboard, and scheduled deletion (the 90-day purge exists but is not scheduled). The owner confirmed on #177 (2026-09-25) that this metadata-only approach is right for the family-and-friends MVP; a notice to families is deferred to full production (#186). One part was inert: a document-correction record the relay builds was never used until PR #215 connected the route that produces it (#178; see Fixed). #177, PR #181.
- **Activities the family can vote on now appear on a new trip.** A trip built from an interview lists its not-yet-booked attractions on the "Activities and places" tab as votable items; attractions already booked stay on Bookings only. Votes survive a re-provision. Benefits travellers and organizers. #169, PR #171. (Classic site's RSVP section still cannot render; tracked in #170.)
- **Each phase of a new trip can get a season-appropriate packing list, and only when the place and the season are known.** A short bilingual list, chosen from the phase's named city and every month the phase covers, with no network or model call. A phase that names no city the system knows, or a place with no clear winter and summer (tropical, desert, Mediterranean, monsoon), or a phase that spans seasons, gets no list, and the site shows its generic one. Benefits travellers. #162, PR #165; reworked to abstain by PR #197 (see Fixed). The first version chose a hemisphere from the trip's destination and defaulted north.
- **A real "Other" button on the trip-type question in the interview.** Tapping it makes the organizer's next typed message the answer, kept as written rather than as the word "other". Only that one question allows it, because the other answers must be bilingual on the site. The multi-select "Done" half of #42 is not built. Addresses #42 (partly; still open), PR #150.
- **Health, Money and Communication on the Info tab are now filled.** The tab used to render three empty lists. The control plane now keeps this information per country, re-checks it monthly, and a new trip picks it up when it is provisioned; hospitals and age notes are deliberately left out. Existing trips do not change until re-provisioned. Known gap: a destination only gets data if the interview looked up that country (#159). #156, PR #160.
- **Operator: an organizer can be handed an interview link without a password.** The operator (or the monitoring bot on their say-so) creates the trip and gets a ready-to-forward message in English or Hebrew; a returning organizer gets a short "welcome back" that says their earlier trip is untouched. Off unless the operator key is configured; rate-limited, audited, no password reset anywhere. A trip now remembers its own companion, so `/switch` back to an earlier trip no longer lands on "still finishing your assistant". PR #95.
- **Operator: `create-trip-link` is now in the repository.** One address in, a production account plus a Telegram interview link out; safe to repeat. It was previously a single untracked file. PR #148.
- **A new trip's stored data (photos, bookings, site database) is filed under the trip's id, not its slug.** A reused slug can no longer meet a previous family's data. Existing trips keep their current directory. PR #89.
- **Uploaded documents are kept, reconciled and handed to the trip (Slice B of #92).** Original files are stored once and read once per version; documents are merged with what the organizer already said and disagreements are reported rather than overwritten; documents reach the provisioned trip behind authentication; a super admin's `/model` override is now re-read from the database every 30 seconds by the running relay (before, it was recorded but never applied). Migrations are timestamp-named with a rollback header. Keeping originals needs a document-store directory: a deployment that sets the "required" flag refuses to start without a real mounted volume, any other run only warns and works without keeping originals. Whether any deployment sets it is not stated here. #92, PR #145 (forward-ported to this branch; no separate PR number).
- **Documents can add to an interview answer instead of being refused (Slice A of #92).** A document about a question that already has an answer now fills gaps and adds entries without replacing anything, and readers cope with spreadsheets whose dates are numbers, JSON exports holding JSON as text, and PDFs whose text is split up. PR #136 addresses #49, #52, #53, #54, #55, #59 and #60 (its description says each was verified against its own test); those seven are now closed on GitHub, by hand on 2026-09-25 with evidence comments, while the fix is on the sprint branch only. It advances #51 and #56, which stay open. #92.

### Fixed

- **A change the organizer types to the interview's held answers was silently overwritten or dropped.** An organizer who typed a correction to a stop or a traveller the interview already held could lose what was already captured, and a return to a place already visited replaced the first visit. Now the interview shows exactly what it understood and what stays, warns about confirmed bookings when a stop or traveller is removed (and says "non-refundable" only where the data says so), and applies the change only after the organizer confirms. A return leg is kept as a second stop; a removal that carries many bookings can be typed; names with Persian, Indic or emoji characters are kept; a preview Telegram refuses can always be cancelled. Benefits organizers. **Not deployed, and acceptance is still owed:** a real-model run in English and Hebrew, a walk on the test bot, the document walk on a throwaway trip (#217), the owner's read of the Hebrew wording, and three follow-ups before this sprint reaches families (#225 items 1, 3 and 5). #206, #205 and #114 stay open (addressed by, not closed by, the PR; #114 is broader than the return-leg fix). PR #199.
- **A down assistant no longer talks over the family group, and an organizer's documents in a private chat are read again.** Two problems in the relay. (1) While a trip's assistant was unreachable, every message in the family group got "I'm still finishing your assistant", including the family talking among themselves. Now, once the assistant has been announced as up, the group stays quiet unless someone addresses it, and an addressed message gets one short line per chat per ten minutes ("I'm off for now — hoping to be back soon", English or Hebrew); a private chat gets the same wording. A trip whose assistant was never announced still says "still finishing". (2) A document an organizer sent in a private chat never reached the reader that proposes changes to the trip, because the router checked for the attachment before it had been attached; it now does. Benefits families and organizers. **Nothing changes for anyone until the control-plane API is rebuilt and the relay restarted, and it is not deployed anywhere.** **The path a document now takes has not been walked end to end:** approving a proposal re-provisions the organizer's site, this route had never run in production before, and it must be walked on a throwaway trip before this sprint reaches the VM (#217). Known gaps: the once-per-outage organizer notice and recovery are #187, and the family-group behaviour is only its core, so #179 stays open (addressed by PR #215); the ten-minute limit is forgotten when the relay restarts. #178 is closed on GitHub, PR #215.
- **A trip site's gallery and social data were readable without logging in, and one member's private details reached the others.** Anyone with the site's address could list the family's photos, fetch the files, and mint public album share links; the comment, RSVP, reaction and task lists attached each member's Telegram id, Google email and age to what other members saw; the logo route could serve arbitrary files; and an uploaded HTML or SVG file could run script in another member's browser. Now the gallery and social lists need a login, other members show only name, colour and avatar, photo files sit behind links that expire after an hour, the logo route serves only images inside the trip's folder, uploads accept images only under a generated name with protective headers, and the trivia TV stream no longer carries the family a player belongs to. A photo's share link (`/photo/…`) is an unguessable link that does not expire and works for anyone who holds it (owner decision, 2026-09-25: everyone in the group). Benefits every family on a trip; security fix. **Nothing changes on a running site until a release carrying it is promoted and each trip is redeployed by hand; nothing is deployed.** The site's built front end was rebuilt in the same change so photos display. Known gaps, tracked: the classic site still runs a participant's name or colour as script (#213), unauthenticated lost-and-found writes with no rate limit (#207), who may mint public album links and smaller inconsistencies (#210), and further follow-ups (#212). #191, #194 and #208 are closed on GitHub, PR #211.
- **Operator: model calls could see the whole environment of the process that made them.** Every model subprocess (Codex, Claude, Hermes) now starts with an explicit allow-list of environment variables instead of inheriting the relay's, so a crafted document or message cannot reach relay secrets through a model tool. The Codex isolation check now also runs when a super admin switches the model with `/model`, and document reading now takes its effort setting from the deployment's configuration like its runner and model, so the Claude CLI no longer reads untrusted documents under the operator's personal settings, hooks and connectors. Not covered: the same full-environment pattern remains in the trip assistant's own extraction helper (#183). Benefits the operator; security fix. **A running relay picks this up only after the API is rebuilt and restarted, and the change is not deployed anywhere.** Known effects and gaps, tracked in #202: a Hermes provider key that only the relay held is no longer passed on and belongs in the Hermes environment file; document reading on the Mac moves to a medium effort whose quality has not been measured; the VM's effort setting is undecided. Closes #153 and #58, PR #192.
- **A trip site could serve a configuration field nobody chose to show.** The site removed a list of known-private fields from a trip's configuration before serving it, so any field nobody had thought to list reached every signed-in family member. It now serves only fields on an explicit list of what the site and the assistant need, and drops the rest (with a count of dropped fields). Benefits every family on a trip; security fix. **Nothing changes for anyone yet:** new trips get it once a release carrying it is promoted, and each existing trip keeps its current site until it is redeployed by hand. Redeploying an existing trip can hide fields it shows today (the audit found 40 fields of 12 kinds on the USA trip's local configuration, for example), so each redeploy is a decision; tracked, with some small defects the audit found, in #200. Closes #172, PR #196.
- **Packing lists could be wrong for the place and the season.** The first version of the per-phase packing list guessed a hemisphere from the trip's destination and defaulted to north, so a city-only destination such as Sydney, a multi-country trip, or a Hebrew spelling with a geresh could get winter items in summer, and a tropical or desert stop could get a "warm jacket" list. A phase now gets a list only when its named city is known to have a real winter and summer and every month it covers is clearly one season; otherwise it gets none and the site shows its generic list. This only ever removes packing output; nothing is added. The UK stays temperate, with the Isles of Scilly excepted. Benefits travellers. Nothing changes for anyone until a release carrying it is promoted and a trip is built or rebuilt on it. Known gaps, tracked in #201: the climate table's borderline months are not yet checked against a published source, and no coverage on real destinations has been measured. Closes #167, PR #197.
- **A failed attempt to connect an assistant to its trip was being erased, so nobody could see it.** When a new trip's assistant could not be wired to the trip's data, the failure was recorded, and then a chat successfully binding to the trip overwrote it with "reachable". The operator's monitoring never saw an assistant that could not read its own trip. The record of the failure is now kept. This is not a fix for the underlying problem: #119 stays open because the root cause is not established, and trips already running are not helped by this change. A repair-path regression to sort out before the sprint's release reaches the VM is tracked in #193. Benefits the operator. Addresses #119 (still open), PR #182.
- **A torn-down trip could still be attached to a chat.** After teardown, a chat (or a group binding link valid for 7–30 days) could be bound to the retired trip, leaving a companion that could never connect: the operator's release verify stayed red and every relay restart waited 40 seconds for it. All five places that could do this now refuse a retired trip (the group link, the operator invitation, the wait for a new trip's assistant, the trip list, and the `/switch` command), and teardown revokes still-live group links (ordering chosen to avoid a database deadlock). One narrow timing race remains: a chat can still end up bound to a trip that is torn down in the same instant as the check. It is left unlocked on purpose, because a lock caused the deadlock above, and it is documented in the code; recovery is to `/switch` to another trip or re-run teardown. Benefits the operator. #105 and #175 are closed on GitHub (by hand, with evidence comments); the fix is on the sprint branch only. PR #174, PR #176, PR #180.
- **Documents with no type or name from Telegram were refused.** A PDF sent as a phone "share/save as PDF" arrived typeless (as `.bin`) and was rejected on a live trip. The file type is now recognised from the file's own bytes (PDF, JPEG, PNG, GIF). Files with a genuinely malformed PDF trailer still fail; that is separate. Benefits travellers. #163 (still open), PR #166.
- **A chat could be bound to a trip on an unverified hint.** Bindings and companion introductions now come only from a verified Telegram identity or the chat the interview ran in; without one the bind is refused and the reason recorded. The unverified id may still be used to send a notification, never to route or authorize. Security fix. #32 is closed on GitHub (by hand, 2026-09-25); the fix is on the sprint branch only. PR #149.
- **Operator: model calls for the interview ran with more of the machine's environment than needed.** The Claude CLI path now passes an allowlisted set of variables, and the Codex path is isolated from shell, web and tool access and from relay secrets. Reduces what a crafted document could reach. PR #91, PR #144; completed for the Claude and Hermes paths and the Codex check by PR #192 (see above).
- **Teardown adopted an IP pool it never uses.** A pool set in the environment could be picked up by teardown, colliding with a range the live control plane reserves. Teardown now carries none. Benefits the operator. PR #108.
- **Ticketed events, shuttles and parking were filed as "other".** A booked event, shuttle or parking stopped reading as a booking on the site. They are now treated as bookings, matching a fix already on main. Benefits organizers and travellers. PR #143.
- **Journey, Today and weather views disagreed with the trip's dates.** During a trip Journey now opens on the current day and phase; Today no longer shows a past activity when nothing is upcoming; weather follows the trip from the first destination through later phases. Benefits travellers. Already on main. PR #152 (merged to main; carried here as `59ed025`).
