# Session pitfalls — 2026-09-09

## Interview MCP server down — all `mcp__interview__*` tools absent

**Symptom:** The tool `mcp__interview__get_interview_for_chat` does not appear
in the available tools list at all. The error is "Tool does not exist" (not a
transport error or a 404 from the interview server — the tools simply aren't
registered). This happens when the interview MCP server is not running.

**Diagnostic steps (confirmed working):**
```bash
# 1. Check if anything is on port 4311
lsof -i :4311

# 2. Check for related processes
ps aux | grep -i "interview\|kinerary\|4311" | grep -v grep

# 3. Read gateway state (does NOT confirm MCP tool availability)
cat ~/.hermes/profiles/trip-intake/gateway_state.json

# 4. Try a direct curl to confirm unreachability
curl -s --max-time 5 http://127.0.0.1:4311/health -H "X-API-Key: <key>"
# exit_code 7 = "Failed to connect to host" = server is down
```

The MCP server URL and API key are in:
`~/.hermes/profiles/trip-intake/config.yaml` under `mcp_servers.interview`.

**What to do:**
1. Do NOT retry the tool — it is not in the tool list, retrying will not help.
2. Do NOT tell the organizer the interview is broken.
3. Write an issue notification immediately:
   ```json
   {"kind":"issue","message":"Interview MCP server (port 4311) unreachable — all interview tools missing. Restart required."}
   ```
4. Stop the turn. The router will re-open when the organizer writes next and
   the server is back up.

**Key distinction from a 404 mid-session:**
- A 404 from `say_for_chat` means the turn ended (nextQuestion is null) — normal.
- "Tool does not exist" on `get_interview_for_chat` means the MCP server is
  completely down — requires admin intervention.

## Gateway state ≠ MCP tool availability

`gateway_state.json` shows `"gateway_state": "running"` even when the interview
MCP server is down. The gateway being up only means Hermes itself is running
and the relay is connected. The interview MCP server is a separate process
that must be running independently on port 4311. Never infer MCP tool
availability from gateway state.
