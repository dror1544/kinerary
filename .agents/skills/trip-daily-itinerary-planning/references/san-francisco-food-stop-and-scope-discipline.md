# San Francisco example — protect day scope and avoid overfeeding the plan

Use case from session:
- Sunday had a fixed noon sports-bar World Cup anchor and a timed dinner reservation later.
- Monday was being replanned as a separate city day.
- The user explicitly said not to touch Sunday while discussing Monday.
- User also cared about not being too full before later food stops.

## Lessons

### 1) Freeze the non-active day once the user narrows scope
When the user says to return to one specific day only, stop carrying new ideas back into the other day.

Good behavior:
- "Okay, we leave Sunday as-is and only adjust Monday."

Bad behavior:
- continuing to re-plan Sunday while supposedly working on Monday

### 2) Distinguish meal vs snack vs dessert stops
In this session the user considered:
- sushi during the game window
- Union Square later
- Cheesecake Factory stop
- dinner later in the day

The right planning question is not "can these all fit geographically?" but also:
- will this make the family too full?
- is Cheesecake a dessert/coffee stop or a real meal?
- is the neighborhood attractive mainly for snacking, in which case it should move later?

### 3) Kura + Union Square + Cheesecake was a bad density fit
Even if the geography had worked, stacking:
- Kura sushi
- then Union Square
- then Cheesecake Factory
- then later dinner
would likely feel too heavy.

Preferred framing:
- if Cheesecake is important, keep it to coffee + shared slice
- if a full sushi meal happens, do not also plan a second filling dessert stop before dinner

### 4) Snack neighborhoods belong later when the user wants to nibble
Chinatown was better later in the day because the user explicitly liked it for:
- stalls
- small bites
- bakery items
- browsing without getting overly full early

## Reusable phrase
- "Let's keep Cheesecake as a small coffee-and-shared-slice stop so it doesn't ruin dinner later."
